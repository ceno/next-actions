## 2. i18n is now fully routed

Overnight flagged this as "half done — cheap now, expensive after M3". It is done.

I got the API from Atlassian's client-library localization docs rather than guessing, and one detail
shaped the design:

- **`t.localizeKey(key, data)` is synchronous** and returns a string, not a Promise. That is the only
  reason `computeBadges` could take a localizer while staying pure and sync.
- `TrelloPowerUp.util.initLocalizer(locale, { localization })` returns a Promise and must resolve
  before the first lookup in an iframe.
- `t.localizeNode(el)` keys off `data-i18n-id`.
- Bundles are flat JSON with `{placeholder}` replacement.

### Two string sites overnight missed

Overnight's report says every user-visible string was centralised in `LABELS`. Two were not:

1. **The badge tooltips in `badges.ts`** — `'{name} — {done} of {total} items finished'`,
   `'finished'` / `'not finished'`, and the `'Checklist'` / `'Item'` empty-name fallbacks. These are
   the accessible long form that SPEC §3.7 leans on, so they are the *last* strings that should have
   been unreachable to a translator.
2. **`'Next Actions'`**, hardcoded as the popup title in two capabilities in `connector.ts`.

Both are now `LABELS` entries and both go through the localizer.

### How it is wired

- `src/i18n.ts` — `LOCALIZATION`, `interpolate`, `english`, `localizer(t)`, `initIframeLocalizer(t)`.
- `public/strings/en.json` — the bundle Trello actually fetches.
- `LABELS` stays the compile-time English **and** the fallback. Every lookup is guarded: a missing
  `localizeKey`, a throw, an empty result, or the key echoed back all fall back to English. A badge
  is never allowed to fail because a translation did not load.
- `computeBadges(checklists, settings, policy, caps, localize?)` — a fifth optional parameter,
  defaulting to `english`. Every existing call site and every golden test is unchanged by
  construction, and the function is still pure: `i18n.ts` imports Trello's types with `import type`,
  which erases, so nothing Trello-shaped reaches `badges.ts` at runtime.
- `authorize.html`'s inline untyped script moved into `src/authorize.ts`, localized, with the English
  copy left in the HTML as the pre-JS fallback and tagged `data-i18n-id`. It also now disables the
  button while authorizing — a second click opened a second window that could never resolve — and
  surfaces the failure instead of swallowing it.

### The build gap this turned up

`vite.config.ts` sets `publicDir: false`, so Vite emits only the HTML entry points and what they
import. The locale bundles are fetched at runtime **by URL** and imported by nothing, so they would
not have been copied into `dist/` at all — and the dev server serves everything under `root`, so this
would have worked perfectly in dev and 404ed in production. A small plugin now emits
`public/strings/*.json` to `dist/strings/` under **unhashed** names, which the runtime-built
`resourceUrl` requires. Verified in the build output: `dist/strings/en.json`.

### Tests

125 passing, up from 102. The 23 new ones cover `interpolate`, all five `localizer` fallback paths,
and the injected-localizer route through `computeBadges`.

The load-bearing one is the **drift test**: `en.json` must equal `LABELS` key for key and value for
value. Without it, adding a `LABELS` entry and forgetting the bundle produces a silent fallback to
correct English that nobody ever notices. There are two companions: no bundle may ship for an
undeclared locale, and no bundle may carry a key `LABELS` does not define.

**Mutation-checked, per the standard overnight set.** Three seeded faults — a `LABELS` value drifting
from the bundle, an orphan key added to the bundle, a key deleted from it — and all three are caught.

## 3. A defect the preview found in its first minute

`public/preview.html` renders the real `computeBadges` against a fixture spread. Looking at it
surfaced something no test had:

> **An unnamed check item renders as a bare glyph pill.** `itemBadge` builds its text with
> `join(glyph, item.name)`, and `join` returns just the prefix when the name is empty — so the badge
> text is `☐` and nothing else, while its own tooltip correctly reads `Item — not finished`.

Two things are wrong with that. The text and the tooltip disagree, and `badges.ts` states the
invariant "a badge must never render as an empty or ragged pill" — which it enforces for the *header*
path and not for the item path. `LABELS.fallbackItemName` already exists and is already used by the
tooltip; the fix is to use it in the text too.

**I have not fixed it.** It changes `computeBadges` output, which golden tests encode, and it is
plausibly unreachable — Trello may not permit an empty check item name at all. That is an E-series
question, not a guess to stack. Recorded here rather than silently patched.

## 5. New assumption, tagged

One, and it is small: **Trello's behaviour on a missing key is not documented.** `localizer` treats an
empty result or a result exactly equal to the key as a miss and falls back to English. Our keys are
camelCase identifiers, never real copy, so a genuine translation cannot collide with one. If Trello
in fact returns `undefined` on a miss, the guard already covers it.
